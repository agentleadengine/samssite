Claude Code, the agent harness

4 min readLast checked 2026-09-28

Claude Code is Anthropic's coding agent. You can use it in the terminal, VS Code, JetBrains, the desktop app, or web sessions. It works in a project, proposes and makes changes through its available tools, and asks for approval according to your permissions.

The simple explanation.

Claude the model is a brain in a jar, see What is autonomous AI. It can think, write, and plan, but on its own it can't touch anything outside the chat window. A harness is the program that gives the brain hands: it catches the model's requests to use tools, executes those requests, and hands back the results. Claude Code is Anthropic's official harness.

Claude Code is documented across terminal, editor, desktop, and browser surfaces. Its extension points include instructions, auto memory, skills, hooks, subagents, plugins, permissions, and MCP.

~ what Claude Code is made of ~

What ships inside the box.

What you get depends on the surface, account, project configuration, and permissions. These are the core building blocks to learn first:

  • Tools and permissions. Claude Code can use project tools when they are available and permitted. Treat its permission policy as the boundary, not a promise of unrestricted access.
  • A proper permission system. Not a checkbox. You can say: "allow all reads, ask me before Bash commands, deny rm -rf outright." Precise enough to run a real agent without a human watching every step. See Permissions.
  • MCP client support. Any MCP server you configure is available to the model as tools. Install the Notion MCP and the agent can read your Notion in the same session.
  • Hooks. Run your own code on key events (before a tool call, after a session ends, when Claude writes to a file). This is how you automate safety checks, test runs, or reports. See Hooks.
  • Skills. Reusable instruction and workflow packages that Claude Code can load when relevant or when you invoke them. See Skills.
  • Memory. Project instructions in CLAUDE.md and AGENTS.md work alongside Claude Code auto memory. They are related, but not one single user-managed index. See Memory.
  • Sub-agent delegation. You can spawn specialized helper agents for big tasks without polluting the main context window.
  • Programmatic use. Use claude -p or --print for scripts, CI, and automation. Keep permissions scoped to the work the script needs.

Why this is the default starting point.

You could build your own agent harness from scratch. People do. But for almost everyone, Claude Code is the right starting place, for four reasons:

~ why Claude Code by default ~

Claude Code saves you from writing the basic interaction loop yourself. It does not remove the work of choosing safe permissions, reviewing changes, or testing the result. Start with a narrow task and expand the setup only when the workflow earns it.

Install and first run, in 60 seconds.

# macOS, Linux, or WSL native installer
curl -fsSL https://claude.ai/install.sh | bash

# Verify, then start in your project
claude --version
claude

Follow the official installation guide for your operating system and sign in when prompted. A native installation updates in the background. Homebrew and WinGet installations use their package manager for updates.

For scripts, CI, and automation, Claude Code documents non-interactive use with claude -p or claude --print. Scope the environment and permissions to the task.

When Claude Code is NOT the right choice.

Two legitimate reasons to not use Claude Code:

  1. You're embedding an agent inside a product end users interact with. Users don't have terminals. You need to wrap the agent in a web app, mobile app, or Slack bot. In this case, build a custom harness using the Anthropic SDK directly. Claude Code is for developer workflows; for user-facing products, you need more control over the UI.
  2. You're bridging multiple model providers for research or vendor-neutrality. Claude Code is Claude-specific. If you want one harness that can talk to GPT, Gemini, and Claude interchangeably (usually for evaluation research), build your own.

Choose the surface that fits the work, then keep the first task small enough to review.
