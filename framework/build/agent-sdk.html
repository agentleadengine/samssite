The Claude Agent SDK

Track
Builders · build guide
Time
About 30 minutes
You need
Python 3.10+ or Node.js 18+, plus API access
Last checked
28 Sep 2026

The Claude Agent SDK is for putting Claude Code style agent behavior inside a Python or TypeScript application you operate. It is useful when a terminal command is no longer enough and you need programmatic control over messages, permissions, sessions, or the surrounding product.

What the SDK gives you

An agent is more than one model response. It plans, calls tools, reads what happened, and decides what to do next. The SDK packages that agent loop with built-in tools, permissions, sessions, hooks, MCP connections, skills, and context management. Your application consumes the resulting message stream and supplies the boundaries.

The Agent SDK provides the Claude Code agent loop and capabilities in Python and TypeScript. For languages outside those two, Anthropic recommends running the CLI as a subprocess with -p and --output-format json.

Checked28 Sep 2026Source 01

This distinction helps with the first architecture choice. If you need a person at a terminal, use interactive Claude Code. If a script needs one bounded answer, use headless claude -p. If an application needs to manage an agent over time, use the SDK. If you only want raw model calls and intend to write the tool loop yourself, use the Client SDK instead.

Install a minimal Python agent

The official quickstart supports Python with either uv or pip. The example below uses a virtual environment and the Python package. Set your API key in the shell that starts the agent. Do not put it in source code, and remember that the SDK does not load a .env file for you.

python3 -m venv .venv
source .venv/bin/activate
pip install claude-agent-sdk
export ANTHROPIC_API_KEY=your-api-key

Save this as agent.py. It is the documented quickstart pattern: query() returns an asynchronous stream while the agent thinks, uses allowed tools, and returns a result. The prompt asks for a change, so the explicit tool list and edit permission are intentional.

import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage

async def main():
    async for message in query(
        prompt="Review utils.py for bugs that would cause crashes. Fix any issues you find.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],
            permission_mode="acceptEdits",
        ),
    ):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)
                elif hasattr(block, "name"):
                    print(f"Tool: {block.name}")
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype}")

asyncio.run(main())
python agent.py

The SDK quickstart uses allowed_tools to auto-approve specific tools and permission_mode="acceptEdits" to approve file edits. The loop ends when the agent completes the task or hits an error.

For an existing TypeScript project, the corresponding package is @anthropic-ai/claude-agent-sdk. The TypeScript API has the same basic shape: import query, iterate with for await, give it a prompt and options, then handle messages.

SDK, headless, or interactive?

ChooseWhen it fitsWhat you own
Interactive claudeYou are actively developing, exploring, or reviewingThe conversation and approvals
claude -pA script, CI job, or scheduled one-off task needs a resultThe shell command, input, output, and exit code
Agent SDKYour app needs streaming, sessions, callbacks, or embedded controlThe process, interface, permissions, and lifecycle

Headless mode is deliberately small. The basic form is:

claude -p "What does the auth module do?"
claude --bare -p "Summarize README.md" --allowedTools "Read"

Use --bare for a predictable script or CI invocation. It skips automatic discovery of hooks, skills, commands, subagents, plugins, MCP servers, auto memory, and CLAUDE.md. That reduces surprise, but it also means you must pass any context and configuration your task actually needs.

claude -p runs Claude Code non-interactively and exits with status 0 on success. The headless documentation recommends --bare for scripted and SDK calls when you need to avoid loading local project or user configuration automatically.

Keep the first agent bounded

Start with read-only tools when the task permits it. Add Edit only for an output you can inspect or test. Add Bash only when command execution is essential. Let a successful first run prove a narrow contract before adding MCP servers, subagents, custom system prompts, or persistent sessions.

Streaming is helpful for an interactive product because you can show progress. A background worker might instead collect messages and save a concise run record. In both cases, record the prompt, permitted tools, result subtype, and any change requiring review. Those details make a failure diagnosable without storing secrets or raw private inputs unnecessarily.

Mistakes I see often

  • Using the SDK for a single shell task. claude -p is often simpler.
  • Auto-approving too much. Tool names are part of your security boundary.
  • Assuming a subscription login is application authentication. Build products with an approved API authentication method.
  • Ignoring loaded configuration. Use --bare when repeatability matters.

Do this today

  1. Pick a file-level task with a clear pass or fail result.
  2. Run it first with only Read, Glob, and Grep if editing is not required.
  3. Add one test or review step before allowing edits.
  4. Move to the SDK only when your surrounding application needs the message stream or session control.
