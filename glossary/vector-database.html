Vector Database

A database designed to store embeddings and find similar ones fast.

Explained simply.

A vector database searches embeddings by similarity instead of exact text. Its index trades memory, latency, and recall. The result depends on corpus size, hardware, filters, and index settings.

An example.

A parts catalog stores an embedding beside each product. A search for "outdoor extension cable" can retrieve items described as weather-resistant cords, then filter the result to products in stock.

Why it matters.

A small RAG system may use an in-process index or pgvector inside Postgres. A separate managed database becomes useful when filtering, traffic, isolation, or operations exceed that setup.

Pinecone documents indexes that can combine dense vectors, sparse vectors, and full-text search in one schema.

Checked28 Sep 2026Source 01

pgvector adds exact and approximate nearest-neighbor search to Postgres. It can be enough when relational data and vectors belong together.

Three ways to store vectors.

OptionUse it whenWhere it breaks
In-process indexA prototype or offline tool has a small corpus and one process.Shared writes, backups, access control, and multiple app servers.
pgvectorThe app already uses Postgres and needs SQL joins or transactions.The vector index and traffic become hard to fit or tune on the database.
Managed vector databaseElastic traffic, tenant isolation, or managed operations justify another service.Usage meters, network latency, and a second data system add cost.

Latency is measured, not promised. Record corpus size, dimensions, filters, candidate count, recall target, hardware, region, and 95th percentile time.

Do this today

  1. Count vectors, dimensions, writes, and searches.
  2. Write the filters and joins every query needs.
  3. Benchmark the simplest option that fits.
  4. Add a managed service only when the measured limit is clear.
