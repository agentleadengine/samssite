Glossary AI

Foundation Model

A very large, general-purpose model trained on broad data. The base layer that specific applications build on.

Explained simply.

A foundation model learns broad patterns before a team adapts it to a narrower job. Adaptation can use prompts, retrieval, tools, or fine-tuning. Training cost varies by model, data, hardware, and method, so there is no useful universal figure.

An example.

A support tool can call GPT-6 Sol for generation, retrieve the current refund policy, and use a tool to look up an order. The model is one layer in that product.

Why it matters.

Model choice changes capability, latency, price, data policy, and deployment options. Evaluate the whole system because prompts, retrieval, tools, and review rules also affect the result.

OpenAI's current general API tiers are GPT-6 Astra, Sol, and Luna, each with different input and output prices.

The tradeoffs.

QuestionHosted APIOpen-weight deployment
Training and adaptationPrompting, retrieval, tools, and vendor-supported tuningPrompting, retrieval, tools, adapters, or full tuning when the license permits
InferenceThe vendor operates the modelYour team or hosting vendor operates it
LicenseService terms govern useThe model license governs use and redistribution
Data policyDepends on consumer, business, or API termsYou still need policies for hosting, logs, and operators
Main limitProvider changes, quotas, and less infrastructure controlHardware, serving, updates, and evaluation become your job

Do not choose from a leaderboard alone. A model with a better score can still cost more per accepted result or conflict with your data rules.

Do this today

  1. Name the task and the data it touches.
  2. Write the latency, cost, and deployment limits.
  3. Test one hosted and one open-weight option when control matters.
  4. Record the exact model, license, and date.
