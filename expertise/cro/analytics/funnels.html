Funnel analysis

3 min readLast checked 2026-09-28

A funnel is a sequence of defined events. Rank leaks only after checking denominators, segment differences, and downstream value.

Building a funnel

Map the steps: visit → view product → add cart → checkout → purchase. Define the event, denominator, order, and time window for each step.

Interpretation

  • Validate the numerator and denominator before ranking a leak
  • Compare segments such as new versus returning and mobile versus desktop
  • Translate lost users into verified downstream value

Actions

Investigate the step with the largest credible value loss. A large percentage drop can be normal, low value, or caused by a bad denominator.

This sketch counts lost users only. Add qualified value and data-quality checks before setting priority.

Do this today

Hypothetical worksheet: A quote funnel receives 1,000 eligible users. These are planning inputs, not reported results.

StepEvent definitionUsersStep rateLost usersPlanning value of next step
Quote pagequote_view, page template is quote1,000100%0$0
Form startedquote_start, first field changed35035%650$5
Form submittedquote_submit, server accepts record ID7020%280$20
Sales acceptedquote_accepted, CRM status changes3550%35$80

Check that each user appears once, the date window matches, and quote_submit has a CRM record ID. Cut the table by mobile versus desktop and new versus returning visitors.

Page to start loses 650 of 1,000 users, a 65% step drop. Start to submit loses 280 of 350 users, an 80% step drop. The second step has both the larger percentage drop and the larger planning loss: 280 × $20 = $5,600, compared with 650 × $5 = $3,250. Investigate start to submit first.

Decision rule: Prioritize verified lost value. Open and closed funnels can use different denominators, so record the funnel type.
